# [11-1] Setup i18n Infrastructure

## Description
Establish the foundational infrastructure for Chrome Extension internationalization including directory structure, TypeScript helpers, and Chrome i18n API integration. This task creates the framework needed for all subsequent localization work.

## Requirements

### Functional Requirements
- Create `_locales/` directory structure following Chrome Extension standards
- Implement TypeScript helper functions for type-safe i18n
- Add `default_locale` to manifest.json
- Create English messages.json with comprehensive string catalog
- Establish message key naming conventions

### Technical Requirements
- Chrome Extension Manifest V3 compliance
- TypeScript type safety for message keys
- No external dependencies (Chrome native API only)
- Backward compatibility with existing codebase

### Quality Requirements
- All message keys follow consistent naming convention
- TypeScript interfaces prevent runtime errors
- Helper functions provide clean API for developers
- Documentation for future maintainers

## Implementation Plan

### Step 1: Directory Structure Setup
```bash
mkdir -p _locales/en
mkdir -p src/i18n
```

### Step 2: Manifest Configuration
- Add `"default_locale": "en"` to manifest.json
- Update extension name/description to use message keys

### Step 3: TypeScript Infrastructure
- Create `src/i18n/index.ts` with helper functions
- Create `src/i18n/types.ts` for message key types
- Implement `getMessage()` wrapper with type safety

### Step 4: Base English Messages
- Create `_locales/en/messages.json`
- Add all identified user-facing strings
- Include descriptions for translator context

### Step 5: Integration Testing
- Test Chrome i18n API integration
- Verify message loading and retrieval
- Validate TypeScript compilation
