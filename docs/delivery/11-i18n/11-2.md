# [11-2] Extract and Organize Translatable Strings

## Description
Systematically identify, extract, and catalog all user-facing text from HTML templates and TypeScript files. Create comprehensive English messages.json with proper translator context and organize strings into logical categories for maintainability.

## Requirements

### Functional Requirements
- Extract all hardcoded user-facing text from popup.html
- Identify dynamic text strings from TypeScript files
- Organize strings into logical categories (auth, forms, errors, etc.)
- Add translator-friendly descriptions for all strings
- Handle placeholder/variable substitution patterns

### Content Categories
- **Authentication**: Login prompts, status messages, privilege errors
- **Form Elements**: Labels, placeholders, validation messages
- **Actions**: Button text, menu items, interactive elements  
- **Status**: Loading, success, error, progress indicators
- **Help**: Tooltips, guidance text, troubleshooting tips
- **Metadata**: Extension name, description, manifest strings

### Quality Requirements
- Every string includes context description
- Message keys use consistent naming convention
- Placeholder syntax follows Chrome i18n standards
- No user-facing string remains hardcoded

## Implementation Plan

### Step 1: HTML Text Extraction
Identify all user-facing text from popup.html:
- Headers and titles (h1, h3 elements)
- Form labels and help text
- Button text and aria-labels
- Placeholder text in inputs
- Static content in divs and spans

### Step 2: TypeScript String Analysis
Extract dynamic strings from source files:
- Status messages in state management
- Error messages and alerts
- Success confirmations
- Loading and progress text
- Console user messages (if any remain user-facing)

### Step 3: Message Organization
Organize into logical key structure:
- `auth_*`: Authentication-related messages
- `form_*`: Form labels and inputs
- `button_*`: Interactive element text
- `status_*`: Status and state messages
- `error_*`: Error messages and alerts
- `help_*`: Help text and guidance

### Step 4: Context Documentation
For each message, provide:
- Clear description of where/when it's used
- Context about user situation
- Notes about character length constraints
- Placeholder variable explanations

### Step 5: Validation
- Cross-reference with existing UI states
- Ensure no strings are missed
- Verify placeholder syntax
- Review descriptions for clarity
