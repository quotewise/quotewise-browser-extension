# [1-12] Service Worker Resilience & Security Hardening

## Description

Ensure Manifest V3 compliance with ephemeral service worker handling and add security hardening for content script data. MV3 service workers can be terminated at any time, so the extension must gracefully handle restarts and validate all incoming data.

## Requirements

### Functional Requirements
- Extension must recover gracefully after service worker termination
- Invalid content script data must be rejected with clear errors
- CSRF requests must fail safely when token unavailable

### Technical Requirements
- Service worker state persisted to `chrome.storage.local`
- Input validation for all content script messages
- `cookies` permission declared in manifest

### Security Requirements
- Content script data validated before storage/transmission
- CSRF token fallback must NOT proceed without token (current behavior is dangerous)
- No sensitive data logged to console

### Issues to Address
1. **Service Worker State Loss** (`service-worker.ts:12-14`):
   ```typescript
   let apiHandler: ReturnType<typeof initializeApiHandler>;
   let authMonitor: AuthenticationMonitor;
   let storageCleanup: ReturnType<typeof initializeStorageCleanup>;
   ```
   These global variables lose state when service worker terminates.

2. **Missing Input Validation**:
   - Content script tweet data passed directly to storage without validation
   - Message structure not validated

3. **CSRF Fallback Risk** (`csrf-utils.ts:67-94`):
   - If token retrieval fails, requests proceed without CSRF token
   - Should fail safely instead

4. **Missing Permission**:
   - Code uses `chrome.cookies` API but permission not declared

## Implementation Plan

### 1. Service Worker State Persistence

**Modify `src/background/service-worker.ts`**:
```typescript
// Replace global variables with lazy initialization
async function ensureServicesInitialized(): Promise<void> {
  if (!apiHandler) {
    apiHandler = initializeApiHandler();
    authMonitor = new AuthenticationMonitor();
    storageCleanup = initializeStorageCleanup();

    // Restore any persisted state
    const { serviceState } = await chrome.storage.local.get('serviceState');
    if (serviceState) {
      authMonitor.restoreState(serviceState.authState);
    }
  }
}

// Call in message handler before processing
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  ensureServicesInitialized().then(() => {
    // Handle message
  });
  return true;
});
```

### 2. Create Input Validators

**Create `src/utils/validators.ts`**:
```typescript
import type { TwitterData } from '../platforms/types';

export function validateTwitterData(data: unknown): data is TwitterData {
  if (!data || typeof data !== 'object') return false;
  const d = data as Record<string, unknown>;

  return (
    typeof d.text === 'string' &&
    d.text.length > 0 &&
    d.text.length < 10000 &&
    typeof d.author === 'string' &&
    typeof d.url === 'string' &&
    d.url.startsWith('https://')
  );
}

export class ValidationError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'ValidationError';
  }
}
```
